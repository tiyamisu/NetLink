How TCP Works Here

  1. 1 Browser sends HTTP POST to bridge on port 5000
  2. 2 Bridge opens TCP connection to C server on port 9090
  3. 3 Three-way handshake: SYN → SYN-ACK → ACK
  4. 4 Bridge sends: REPORT|severity|traffic|road|…
  5. 5 Server validates, assigns ID and calculates priority
  6. 6 Server replies with JSON → bridge forwards to browser
Priority formula: Severity + Traffic where Low=1, Medium=2, High=3.
Total 2=LOW, 3–4=MEDIUM, 5=HIGH, 6=CRITICAL.

Protocol Demonstration

TCP

Connection-Oriented

  • Requires a three-way handshake (SYN, SYN-ACK, ACK) before data flows
  • Guarantees ordered, reliable delivery of bytes
  • Used for: report submission, list, detail, status updates, PING
  • Messages are newline-delimited because TCP is a byte stream
  • Multiple clients handled by one handler thread each
  • Critical sections protect shared report data
UDP

Connectionless

  • No connection setup – sends a single datagram and returns
  • No delivery guarantee; no ordering; no duplicate detection
  • Used for: location alerts using ALERT_V2 protocol
  • Application-level ACK implemented on top, but UDP itself is still best-effort
  • A successful sendto() does not mean the server received the datagram
  • Server stores only the 10 most recent UDP alerts

Key Networking Concepts

What is a Socket?

A socket is an OS-level endpoint for network communication. In this project, C programs use Windows Sockets (Winsock) initialized with WSAStartup(). A socket binds to an IP address and port to send or receive data.

Three-Way Handshake

TCP connections begin with SYN (client) → SYN-ACK (server) → ACK (client). This is done by the OS TCP stack automatically when your code calls connect() on the client and accept() on the server.

Why Newline Framing?

TCP is a byte stream – there are no message boundaries. A single send() may be received in multiple recv() calls. This server uses newline (\n) as a message terminator so both ends know where one message ends.

Concurrency & Critical Sections

The C server spawns one Windows thread per accepted TCP client. All threads share the report and alert arrays. Windows critical sections (CRITICAL_SECTION) prevent simultaneous writes that would corrupt the shared data.

127.0.0.1 vs 0.0.0.0

0.0.0.0 (INADDR_ANY) means the server listens on all available network interfaces. 127.0.0.1 (loopback) routes traffic back to the same machine. The bridge uses loopback to talk to the server on the same PC.

HTTP as Application Layer

HTTP runs over TCP. The browser speaks HTTP to the C bridge on port 5000. The bridge then speaks the custom text protocol (REPORT, LIST, STATUS, etc.) over TCP to the C server on port 9090.
